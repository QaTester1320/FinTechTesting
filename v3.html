1. Stock Market & Investment Basics

These concepts help testers understand how investment platforms work. Learning finance terms makes it easier to test portfolios, orders, reports, and transactions.

Stocks / Equities

Stocks represent ownership in a company. When users buy shares of a company, they become shareholders.

Example: Buying 10 shares of Infosys means the investor owns a small part of Infosys.

Portfolio

A portfolio is a collection of investments such as stocks, mutual funds, and bonds owned by a user.

Example: A portfolio may contain HDFC Bank stock, SBI stock, and mutual funds together.

Buy / Sell Orders

Users place buy or sell requests on trading platforms. Testers verify order success, failure, and status updates.

Example: User places BUY order for 5 Tata Motors shares and system updates portfolio after execution.

2. Wealth Management Domain Knowledge

Wealth management platforms help advisors manage investors, portfolios, subscriptions, and financial recommendations.

RIA & RA

RIA means Registered Investment Adviser and RA means Research Analyst. These professionals provide investment guidance.

Example: An RIA recommends balanced portfolios based on customer risk profiles.

KYC Process

KYC verifies customer identity using PAN card, Aadhaar, or address proof before investing.

Example: Tester verifies error handling when PAN number is invalid.

Subscription Workflow

Investors subscribe to advisory plans for portfolio recommendations and reports.

Example: User purchases premium advisory plan and gains access to recommendations dashboard.

3. Trading Workflow Testing

Trading systems contain multiple workflows that require accurate validations and role-based testing.

Order Placement Flow

Manual testers verify order creation, confirmation, pending state, and successful execution.

Example: Login → Portfolio → Buy Shares → Order Success Message.

Failed & Cancelled Orders

Testing should confirm proper messages when orders fail because of low balance or market issues.

Example: User balance insufficient → “Order Failed” message displayed.

Role Testing

Advisor and client users should have different permissions and dashboards.

Example: Client cannot access admin portfolio management panel.

4. Financial Calculations Validation

Finance applications rely heavily on accurate calculations. Even a small decimal mistake can create major issues.

Profit & Loss

Verify whether system correctly calculates gains or losses after trades.

Example: Buy at ₹100 and sell at ₹120 → Profit should be ₹20.

CAGR & XIRR

These formulas calculate long-term investment returns and are commonly used in portfolio reports.

Example: Tester validates annual return percentages shown in reports.

Decimal Precision

Finance systems must handle decimal values carefully without rounding errors.

Example: ₹100.5678 should not incorrectly display as ₹100.56 if rounding rules differ.

5. API Testing Basics

APIs allow frontend systems and backend systems to communicate. Manual testers often validate API responses using tools.

REST APIs & JSON

REST APIs transfer data using JSON format between systems.

Example: API returns user portfolio details in JSON format.

Status Codes

HTTP status codes indicate API success or failure.

Example: 200 = Success, 401 = Unauthorized, 500 = Server Error.

Postman & Swagger

Postman helps test APIs manually while Swagger documents available APIs.

Example: Tester validates API response body in Postman.

6. Database Testing Basics

Database validation ensures stored data matches frontend actions and transaction results.

SELECT & WHERE Queries

These SQL queries retrieve and filter data from tables.

Example: SELECT * FROM users WHERE user_id=1001;

JOINs & Validation

JOINs combine multiple tables to verify related records.

Example: Verify portfolio table correctly maps to investor table.

Transaction Verification

Testers validate whether successful payments and trades are stored correctly in database tables.

Example: Buy order reflected correctly in transaction history table.

7. Manual Testing Concepts

These are core software testing concepts every QA engineer should know before entering fintech projects.

Test Cases & Scenarios

Test cases define steps and expected results while scenarios describe workflows.

Example: Verify successful login with valid username and password.

Smoke & Regression Testing

Smoke testing checks core features while regression testing verifies old features after changes.

Example: Login tested after every deployment.

Bug Reporting

Defects should include steps, screenshots, expected results, and severity.

Example: “Payment button crashes app after entering invalid CVV.”

8. Security Testing Basics

Finance platforms handle sensitive user information and money, so security testing is extremely important.

Authentication & OTP

Verify login systems, OTP validations, and password security.

Example: OTP should expire after 60 seconds.

Authorization

Users should only access features allowed for their role.

Example: Investor user cannot modify advisor settings.

Session Timeout

Applications should automatically log out inactive users.

Example: User session expires after 15 minutes of inactivity.

9. Payment & Subscription Testing

Fintech platforms often charge advisory subscription fees and process secure online payments.

Payment Workflow

Validate successful payments, failed transactions, and retry functionality.

Example: Incorrect CVV should display payment failure message.

Invoice Generation

Invoices should include GST, payment amount, and transaction details.

Example: PDF invoice generated immediately after successful payment.

Renewal Testing

Subscription renewals should activate plans without duplicate charges.

Example: Annual plan renews automatically on expiry date.

10. Reports & Dashboard Testing

Dashboards display important financial data, charts, filters, and reports for investors and advisors.

Reports Validation

Verify calculations, downloadable files, and displayed financial summaries.

Example: Portfolio report totals should match dashboard totals.

Charts & Graphs

Graph values should accurately reflect backend data.

Example: Monthly growth chart should match stored transaction records.

Filters & Search

Test sorting, pagination, and search functionality with large datasets.

Example: Search investor by PAN number or portfolio ID.

11. Important Fintech Edge Cases

Edge cases are unusual situations that can break financial systems if not tested properly.

Decimal & Currency Issues

Finance apps must display currency and decimals correctly.

Example: ₹1,00,000.567 should not lose decimal precision unexpectedly.

Duplicate Transactions

Systems should prevent repeated orders and duplicate payments.

Example: Double-clicking payment button should not create two transactions.

Date & Market Timing

Trading systems must handle timezone and market opening hours correctly.

Example: Orders placed after market close should remain pending.
