1. Stock Market & Investment Basics

This section teaches the basic money and market terms you will see in apps. Each point has a simple meaning, a quick example, and a visual to help remember it.

Stocks / Equities

A stock means you own a small part of a company.

Example: If you buy 1 share of Tata Motors, you own a tiny piece of Tata Motors.

NSE & BSE basics

These are places where stocks are bought and sold in India.

Example: NSE and BSE are like big online markets for shares.

Portfolio

A portfolio is the full list of all your investments.

Example: Your portfolio may have stocks, mutual funds, and gold together.

Holdings vs Positions

Holdings are the stocks you already own. Positions are active trades you are doing now.

Example: Shares bought last month are holdings. A trade opened today is a position.

Buy / Sell orders

A buy or sell order is a request to trade shares at a chosen price.

Example: “Buy 5 SBI shares at ₹600” is a buy order.

Mutual Funds basics

A mutual fund collects money from many people and invests it for them.

Example: You put ₹1000 into a fund, and the fund manager spreads it across many stocks.

Profit & Loss (P&L)

P&L shows how much money you made or lost.

Example: Buy at ₹100 and sell at ₹150 means ₹50 profit.

CAGR

CAGR shows the average yearly growth of money over time.

Example: If ₹10,000 becomes ₹20,000 in 5 years, CAGR tells the smooth yearly growth rate.

XIRR

XIRR is used when money is added or removed on different dates.

Example: If you invest in January and again in March, XIRR calculates the real return correctly.

Portfolio Rebalancing

Rebalancing means adjusting your mix back to the planned ratio.

Example: If stocks become too high in your portfolio, you sell some and move back to the target mix.

Nifty 50 / Sensex basics

These are indexes that show how the top market companies are doing.

Example: If Nifty rises, it usually means many big companies are doing well.

Asset Allocation

Asset allocation means putting money into different buckets.

Example: 50% stocks, 30% gold, 20% cash is one allocation plan.

Risk Profile

Risk profile tells how much risk a person can handle comfortably.

Example: A young user may accept more risk, while a retired user may prefer safer options.

Broker integration basics

Broker integration connects your app to a broker platform to place trades.

Example: The app sends an order to Zerodha or Groww to complete the trade.

Demat account basics

A Demat account stores your shares in digital form.

Example: Just like a bank account holds money, a Demat account holds shares.

2. Wealth Management Domain Knowledge

This section explains how advisor platforms work and how client information moves through the system. Use it to understand platform flow, approvals, and subscriptions.

RIA (Registered Investment Adviser)

An RIA gives advice for the full portfolio, not just one stock.

Example: “Invest 20% in stocks, 50% in mutual funds” is portfolio advice.

RA (Research Analyst)

An RA studies stocks and gives research-based ideas.

Example: “This stock may perform well” is research advice.

Client onboarding flow

This is the first journey of a new client inside the app.

Example: User signs up, enters details, and becomes an active client.

KYC process

KYC checks the identity of the customer.

Example: PAN card and Aadhaar upload may be used to verify the person.

Advisory subscription workflow

This is the flow for selecting and paying for a plan.

Example: User picks a monthly plan and pays before using advice features.

Investor profile management

The app stores user goal, age, income, and risk level.

Example: “Save for house in 5 years” is one profile goal.

Fee/subscription plans

These are the payment choices shown to the client.

Example: Monthly plan, yearly plan, or one-time payment.

Portfolio recommendation flow

The advisor sends an investment suggestion and the client reviews it.

Example: Advisor sends a plan, client opens it, and clicks approve.

Client communication workflow

This is how the platform sends messages, reports, or updates to clients.

Example: The advisor shares a market update inside the app, not through random chat apps.

Platform view idea

One user sees client screens, while another sees advisor screens.

Example: A client sees investments. An advisor sees many client portfolios.

3. Trading Workflow Testing

This section is very important for manual QA in fintech. It teaches the main trade flow and what should happen when orders succeed, fail, or wait.

Login → Portfolio → Buy/Sell → Order placement

This is the main user journey for trading.

Example: User logs in, checks balance, selects Wipro, enters quantity, and clicks Buy.

Order confirmation flow

After placing an order, the app should show confirmation clearly.

Example: “Order placed successfully” should appear after valid trade submission.

Failed orders

Failed orders happen when something goes wrong.

Example: If money is not enough, the order should fail with a clear message.

Pending orders

Pending means the order is not finished yet.

Example: Market closed, so the trade is saved and waits for market opening.

Cancelled orders

Cancelled means the user or system stops the order before completion.

Example: User clicks cancel before the order reaches exchange.

Portfolio update after trades

The portfolio should change after buying or selling shares.

Example: If you buy 2 shares, the holdings count should increase immediately.

Advisor vs Client permissions

Different users should see different things based on their role.

Example: Client cannot see admin-only controls, but advisor can.

Multi-user role testing

Test with more than one user type to make sure access is correct.

Example: One user is a client, another is an advisor, and both get their own views.

4. Financial Calculations Validation

Finance apps must calculate money correctly. Even a tiny mistake can cause a big bug, so this section focuses on checking formulas and rounding carefully.

Percentage calculations

Check if percentage values are shown correctly.

Example: 20 out of 100 should show 20%.

Profit/Loss calculations

Check whether the app calculates profit or loss properly.

Example: Buy at ₹100 and sell at ₹150 means ₹50 profit.

CAGR validation

CAGR should match the correct yearly growth formula.

Example: Use the same data in Excel and compare both results.

XIRR validation

XIRR is used when payments happen on different dates.

Example: Money invested in January and March needs a date-based return check.

Portfolio allocation %

All parts of the portfolio should add to 100%.

Example: 40% stocks + 60% gold = 100%.

Brokerage calculations basics

Brokerage is the small fee charged for trading.

Example: If trade amount is ₹1000 and brokerage is ₹5, total becomes ₹1005.

Tax/GST basics

Tax adds extra cost to the final amount.

Example: 18% GST on ₹100 is ₹18, so the total is ₹118.

Decimal precision checks

The app should not lose paise or cents in calculations.

Example: ₹10.556 should be shown correctly with the right rounding rule.

Rounding validations

Rounding should happen in a proper and expected way.

Example: ₹10.555 may round to ₹10.56, not ₹11.

5. API Testing Basics

Even manual testers in fintech often check APIs because APIs carry important data between frontend and backend. This section explains the basic terms in a very simple way.

REST APIs basics

API is the bridge between app screens and server data.

Example: The app asks for stock price, and the API sends the answer.

JSON basics

JSON is a simple text format used to send structured data.

Example: {"name":"Apple","price":150}

Request/Response validation

Check that what you send and what you get back are correct.

Example: If you send invalid data, the API should return an error, not success.

Status codes

Status codes tell whether the API worked or failed.

Example: 200 means success, 401 means unauthorized, 404 means not found.

Authentication tokens

Tokens act like digital keys for login security.

Example: Without token, the API should block access.

API validation using tools

Testers use tools to send requests and inspect responses.

Example: Send the request and check if the response data is correct.

Postman

Postman helps testers send API requests easily.

Example: Paste the API URL in Postman and click Send.

Swagger

Swagger shows and tests API endpoints in a clean way.

Example: Open Swagger, choose an endpoint, and test the response.

6. Database Testing Basics

Database testing helps you check whether data saved in the backend is correct. It is useful when you want to compare UI data with stored data.

SELECT queries

SELECT is used to fetch data from a table.

Example: SELECT customer_name FROM users;

WHERE conditions

WHERE helps filter the exact rows you need.

Example: Find only the user with user_id = 5.

JOINs basics

JOIN combines data from two or more tables.

Example: Join users table and portfolio table to see customer holdings.

Aggregate functions

Aggregates do calculations like SUM, COUNT, AVG.

Example: SUM of all trade values gives total trade amount.

Data validation

Check if database data matches the front screen data.

Example: If UI says 10 shares, DB should also store 10 shares.

Transaction verification

Verify that a transaction really saved correctly.

Example: After payment, the transaction row should appear in the table.

Portfolio data checks

Confirm portfolio values, quantities, and totals in DB.

Example: Holdings count in DB must match portfolio page count.

7. Manual Testing Concepts

This section covers core QA knowledge used in almost every testing job. These are the basics of how testers plan, write, execute, and report tests.

Test case writing

A test case tells exactly how to test one feature.

Example: Enter username, enter password, click login, expect dashboard.

Test scenarios

A test scenario is the bigger idea of what to test.

Example: “Test login” is a scenario, while the steps are the test case.

Smoke testing

Smoke testing checks if the main app flow is working.

Example: Open app and see if login works before deeper testing.

Regression testing

Regression checks whether old features still work after a change.

Example: After a new update, the old buy flow should still work.

Functional testing

Functional testing checks whether each feature works as expected.

Example: Clicking Buy should place a buy order.

UI testing

UI testing checks how the screen looks and behaves.

Example: Button text should not cut off on mobile.

Integration testing

Integration testing checks if modules work together.

Example: Frontend, API, and DB should work as one flow.

Sanity testing

Sanity testing is a quick check of one new or fixed feature.

Example: After a small fix, test only that feature first.

Exploratory testing

Exploratory testing means testing like a real user without too much planning.

Example: Click around and see if anything breaks unexpectedly.

Defect lifecycle

This is the journey of a bug from open to closed.

Example: New → Assigned → Fixed → Retest → Closed.

Bug reporting

A bug report tells the developer what happened and how to reproduce it.

Example: Steps, expected result, actual result, and screenshots.

RTM basics

RTM links requirements with test cases so nothing is missed.

Example: Requirement “UPI payment” should have matching test cases.

Jira and TestRail

Jira tracks bugs and tasks, while TestRail stores test cases.

Example: Log a defect in Jira and keep the test case in TestRail.

8. Security Testing Basics

Finance apps handle sensitive data, so security testing is very important. This section covers login safety, access control, and secret data protection.

Authentication

Authentication means checking who the user is.

Example: Login with username and password.

Authorization

Authorization means checking what the user can do.

Example: Normal users should not open admin pages.

Role-based access

Different roles should get different permissions.

Example: Client, advisor, and admin all see different screens.

Session timeout

The app should log the user out after inactivity.

Example: If the user is idle for 15 minutes, the session should expire.

OTP validation

OTP confirms that the user owns the phone number.

Example: Wrong OTP should fail and too many attempts should lock access.

Password rules

Passwords should be strong and hard to guess.

Example: Require letters, numbers, and special characters.

Sensitive data masking

Masking hides private data like account numbers.

Example: Show XXXX-XXXX-1234 instead of the full number.

9. Payment & Subscription Testing

This section focuses on payment flows used by advisory and subscription products. Payment testing is important because money-related bugs are serious.

Subscription purchase flow

Check the full journey from choosing a plan to paying for it.

Example: User selects monthly plan and completes payment successfully.

Payment success/failure

Test both successful and failed payment cases.

Example: Internet lost during payment should lead to a clear failure message.

Invoice generation

The system should create a proper bill or invoice.

Example: Payment success should create a downloadable PDF invoice.

GST calculations basics

GST is tax added to the plan amount.

Example: ₹100 + 18% GST = ₹118 total.

Renewal workflows

Renewal means the subscription is charged again later.

Example: Monthly plan should renew next month automatically.

Failed payment handling

If payment fails, the app should show a clear next step.

Example: Expired card should trigger a message to update payment details.

10. Reports & Dashboard Testing

Reports and dashboards show important financial data visually. Testers must check if numbers, charts, filters, and exports all match the real data.

Financial reports validation

Report values should be correct and match the source data.

Example: Monthly report totals must match backend data.

Dashboard data verification

Dashboard figures should be accurate and updated.

Example: If portfolio value changed, the dashboard total should also change.

Export to PDF/Excel

Export buttons should download the right file.

Example: The Excel file should contain the same columns as the page.

Charts/graphs validation

Graphs should show the real values correctly.

Example: If gold is 0%, the pie chart should not show a gold slice.

Filters & sorting

Users should be able to narrow and order the data.

Example: Sort by date or filter by stock name.

Pagination testing

Pagination checks that data loads correctly across pages.

Example: Page 2 should show the next set of records.

Search functionality

Search should find the correct records fast.

Example: Search “Apple” and show only Apple-related records.

11. Important Fintech Edge Cases

Edge cases are unusual or risky cases that can break finance apps. These are very important because they often reveal hidden bugs.

Decimal precision issues

Check whether the app keeps correct decimal values.

Example: ₹10.556 should not be shown incorrectly.

Currency formatting

Money should appear in the correct local format.

Example: Indian format should show commas like ₹9,99,99,999.

Large monetary values

Very big numbers should not break the layout.

Example: ₹99,999,999.99 should still display properly.

Negative balance handling

Users should not end up with less than zero money.

Example: If balance is not enough, order should be blocked.

Duplicate transactions

The app should not charge or save the same transaction twice.

Example: Double-clicking Pay Now should not create two payments.

Date/timezone issues

Different timezones can create wrong trading behavior.

Example: Use IST correctly when market timing is checked.

Market timing validations

Trade actions should respect market open and close times.

Example: Orders after market close should be pending or blocked.

Incorrect portfolio totals

The sum of all items should match the total shown.

Example: Two rows of ₹50 should show total ₹100.
